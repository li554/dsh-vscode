# 初中数学新授课课堂演示模板 — Design Specification

## I. Template Overview

| Property | Description |
| -------- | ----------- |
| **Template Name** | math8_lesson_template（数学八上课堂演示模板） |
| **Use Cases** | 初中数学**新授课**的课堂演示（人教版八年级上册及同构教材）；也可用于数学复习课、习题讲评课的"讲—练—结"环节 |
| **Design Tone** | 清爽、理性、留白充足——白底黑字为主，蓝色承担结构，橙色只点重点 |
| **Theme Mode** | Light theme（纯白底 + 学院蓝主色 + 橙色强调） |
| **Page Count** | 13 页（封面 / 学习目标 / 情境导入 / 知识回顾 / 探究新知 / 概念定理公式 / 例题精讲 1 / 例题精讲 2 / 当堂练习基础 / 当堂练习提升 / 易错辨析 / 方法归纳 / 课堂小结） |
| **Audience** | **学生（投影观看）——页面文案一律对学生说话（"你/我们"），不出现"教师""讲解时""让学生""达成标准"等教学管理用语，也不出现模板制作说明。** |
| **Delivery Target** | 希沃白板（Seewo）授课模式导入——见 §VIII 希沃兼容性 |

**一眼识别点**：**纯白底、无任何底纹**，配一条 8×56px 学院蓝圆角竖条 + 56px 黑体页题构成的页眉，页题右侧一枚 40px 线描图标；页脚只有一条极淡的分隔线和一行小字。整体像一页干净的讲义，而不是装饰过的幻灯片。

**设计动因**：初中数学课件的首要任务是**让学生看清算式和图形**。格线、渐变、阴影都会与数学符号争夺注意力，因此本模板刻意"素"：白底保证投影时对比度最高，蓝色只出现在页眉条、卡片标签和强调结论上，橙色仅用于"本页最关键的一句"——一页最多一处。留白是刻意的，公式页尤其如此。

**底部安全区（本模板的硬约束）**：所有页面内容止于 **y=648**，底部 72px（占画布 10%）永久留空。原因是本模板的主要投放环境是希沃白板授课模式，其底部浮动工具条会覆盖页面下沿；若内容排到 y=700，页码与最后一行正文会被工具条压住。页脚分隔线固定在 y=612、页脚文字基线 y=636，封面蓝色通栏固定在 y=584–648。**新增或改写页面时不得越过 y=648。**

**与 `math_middle_school` 的区别**：那个模板是**方格纸底、墨蓝**，偏"板书讲义"气质，含尺规作图页与作业页；本模板是**白底、学院蓝**，偏"投影演示"气质，固定 13 页课堂流程且**不含**作业页，公式以图片槽位承载。

## III. Typography

| Role | Stack | 说明 |
| ---- | ----- | ---- |
| **Title** | `SimHei, "Microsoft YaHei", sans-serif` | 页题与封面主标题走**黑体**——笔画粗壮均匀，投影下比雅黑更"站得住" |
| **Body / Label** | `"Microsoft YaHei", sans-serif` | 正文、卡片文字、页脚 |

- **Body baseline**: 32px（标题 56 / 副标题 36 / 正文 30–32 / 注释 22–24 / 页脚 20）
- 封面主标题 80px、公式页 hero 数字为图片——**仅封面主标题**允许超出常规字号阶梯。
- **字体策略（希沃兼容硬约束）**：全模板只使用 **SimHei（黑体）** 与 **Microsoft YaHei（微软雅黑）** 两种 Windows 系统自带字体，字体栈末尾以 `sans-serif` 收尾。**禁止**出现 `PingFang SC`（macOS 专有，Windows/希沃会回退）、`Verdana` / `Arial` / `Consolas` 等混入项，也禁止嵌入字体。两种字体在任何 Windows 教学机上必然存在，导入希沃不会触发字体替换导致的排版错位。
- 数学符号（± × ÷ ≠ ≈ ≤ ≥ ∵ ∴ △ ≌ ⊥ ∥ ∠ ° → α β）一律用 **Unicode 原生文本**，不使用图片。

## IV. Signature Design Elements

1. **页眉三件套**（除封面、情境导入、课堂小结外的所有内容页）：
   - 圆角竖条 `rect x=60 y=54 w=8 h=56 rx=4 fill=#1B4F9C`
   - 页题 56px 黑体 `#1B4F9C`，基线 `x=88 y=110`
   - 线描图标 40×40 `#4A90D9`，置于页题**右侧**——注意黑体 4 字页题（56px × 4 ≈ 224px）实际占到 x≈312，图标起点须 ≥ x=344，否则会压字。
   - 引导句 36px `#5B6472`，基线 `y=158`
2. **页脚**：`line y=612` 描边 `#EAF0F8`；左侧 20px `#8A93A3` 写「数学 · 八年级上册 · {{TITLE}}」，右侧页码，基线 **y=636**。封面页脚为蓝色通栏 `rect y=584 h=64`（占位至 y=648）。**y=648 以下为希沃安全区，任何页脚元素不得越线。**
3. **卡片语言**：`rx=16`，普通卡 `fill=#F2F6FC stroke=#DCE4F0`；强调卡 `fill=#FDF1E3 stroke=#F5D5AE`，其上文字用 `#B4690E`。**卡片一律不加阴影**——投影时阴影会糊成灰边。
4. **编号圆**：直径 44–56px，`fill=#1B4F9C` 配白字，或 `fill=#E7EFFA` 配蓝字；同一页内混用不超过两种。
5. **公式槽位**（本模板特有）：公式以**透明底 PNG** 承载（`formula_001.png` / `formula_002.png`，256 色，色 `#1B4F9C`），`preserveAspectRatio="xMidYMid meet"`。这样做的原因是 SVG 文本无法表达分式、根号、上下标的精确排版；换成图片后学生看到的公式与教材印刷体一致。**替换方式见 §VI。**
6. **情境导入页**：满版背景图 `<image ... preserveAspectRatio="xMidYMid slice"/>` 铺满 1280×720，下方叠一层白→透明的渐变 scrim，页题与提问压在下方（页题基线 y=430，三行提问 y=520/570/620）。生成图片时须要求**底部 40% 留空**，否则文字会落在复杂图形上。
7. **色彩纪律**（见 §II）：一页一处橙。
8. **文案人称纪律（本模板特有）**：所有正文以**对学生说话**的口吻书写——用"你/我们"，用"自检："代替"达成标准："，用"提示 1（卡壳时看）"代替"讲解时先让学生……"。页面**不得出现**：教师活动指令、教学法评论（如"让学生看到""人人过关"）、模板制作说明（如"槽位示例，可替换""此处放完整题干"）。

> **图片体积纪律（希沃兼容）**：本模板三张位图合计仅约 117 KB。背景图已从 2616×1472 PNG（2287 KB）压缩为 1280×720 JPEG（35 KB）——**画布就是 1280×720，更大的像素对投影毫无增益，只会拖慢希沃的导入解析**。替换素材时请遵守：位图长边不超过画布对应边（1280 或 720）的 1.5 倍，照片类用 JPEG（quality 80–85），透明公式图用 PNG。
>
> **公式替换方法**：三张图都是**槽位示例**（当前值取自人教版八上 16.3 乘法公式），换课时必须替换。
> - **方法 A（推荐）**：在 PowerPoint 中删除图片，用「插入 → 公式」重新输入——可编辑、可改字号。
> - **方法 B**：生成同规格透明底 PNG（256 色、色 `#1B4F9C`）覆盖同名文件即可，SVG 无需改动。
>
> 封面页的几何主形是**原生 SVG 路径**，不是图片，无需替换。

## VII. Placeholder Overrides

见 frontmatter `placeholders:`。需要说明的几处偏离：

- **`03k_content_method` 显式声明为空列表 `[]`**：该页的四步法与自检问句是跨课通用的方法论，不是每课都要改写的内容。声明为空即"本页无占位符预期"，避免校验器按 `03_content` 默认规则索要 `{{PAGE_TITLE}}`。
- **全部 13 页均未使用 `{{PAGE_TITLE}}`**：本模板的页面标题（"学习目标""探究新知""例题精讲 1"…）**就是模板本身的结构**，不随课程变化，因此写成固定文字而非占位符。这也是 `placeholders:` 必须逐页声明的原因——默认约定会期待 `03_content` 系列含有 `{{PAGE_TITLE}}`。
- **`{{TITLE}}` 只出现在 5 页**（封面 + 学习目标 / 知识回顾 / 探究新知 / 概念定理公式的页脚）：其余页面页脚被内容带占据或使用页码，属版面设计决定。页脚品牌行「数学 · 八年级上册 · {{TITLE}}」可按需整体替换为校本名称。
- **`{{CHAPTER_NUM}}` 与 `{{SECTION_NUM}}` 在封面各出现一次**（"第 N 章　第 N 节"）：**这是两个独立槽位**。早期版本此处误用同一个 `{{CHAPTER_NUM}}` 两次，会渲染成"第 14 章 第 14 节"，已修正。填写时分别给章号与节号。
- **`{{KEY_FORMULA}}`（例题精讲 1）与 `{{SAME_FORMULA}}`（例题精讲 2）语义不同**：前者是"这道题用到的公式"，后者是"变式后仍然相同的那个公式"——刻意分成两个槽位，因为变式页的教学重点正是"公式没变，条件变了"。
- **`{{HINT_1}}` / `{{HINT_2}}`（提升练习）是两级提示**，不是两个平行知识点：第一级提示方向，第二级提示具体中间量。建议按此层次填写。

## VIII. 希沃兼容性（Seewo Compatibility）

本模板的主要投放环境是**希沃白板**。导出 PPTX 并导入希沃前，以下五条已经在本模板层面解决，使用时应予保持。

### 1. 底部 72px 安全区（本模板已内置）

希沃授课模式的浮动工具条覆盖页面下沿。所有页面内容止于 **y=648**（画布高 720 的 90%），底部 10% 永久留空。

| 元素 | 固定坐标 |
| ---- | -------- |
| 内容区下界 | **y ≤ 648**（硬约束） |
| 页脚分隔线 | y = 612 |
| 页脚文字基线 | y = 636 |
| 封面蓝色通栏 | y = 584–648 |

> 若后续自行加页或改版，**不得让任何文字或图形越过 y=648**，否则页码与末行正文会被工具条压住。

### 2. 字体：只用 Windows 系统自带

全模板仅使用 **SimHei（黑体，标题）** 与 **Microsoft YaHei（微软雅黑，正文）**，字体栈以 `sans-serif` 收尾。

- 已移除 `PingFang SC`（macOS 专有，Windows 上必然回退到别的字体，导致行宽变化与错位）
- 已移除 `Verdana` / `Arial` / `Consolas` 混入项
- **不嵌入字体**——嵌入字体在希沃里可能被忽略或替换，反而不如直接用系统字体稳定

### 3. 图片体积：已按画布尺寸压缩

| 素材 | 处理前 | 处理后 |
| ---- | ------ | ------ |
| `situation_intro` | 2616×1472 PNG，**2287 KB** | 1280×720 JPEG，**35 KB** |
| `formula_001.png` | 3056×361，40 KB | 保持（已是 256 色） |
| `formula_002.png` | 3147×361，42 KB | 保持（已是 256 色） |

三张位图合计 **约 117 KB**。原始背景图 2.2 MB 是导入解析失败与卡顿的首要风险源，已按"位图长边不超过画布对应边"的原则降采样。

### 4. 元素复杂度：纯 SVG 基础图形

全部 13 页由 `<rect>` / `<path>` / `<circle>` / `<polygon>` / `<line>` / `<text>` 构成——**没有 SmartArt、没有 3D、没有位图蒙版、没有滤镜**。三张位图是普通 `<image>` 引用。这类结构在 PPTX 里转成原生形状，希沃解析最稳。

### 5. 画布与格式

- 画布 **1280×720（16:9）**，与希沃白板默认比例一致
- 导出务必用 `.pptx`（PPT 2016 及以上格式），不要另存为旧版 `.ppt`

### 6. 文本框宽度：防止导入后文字折叠（转换器已默认处理）

**症状**：PPTX 在 PowerPoint 里显示正常，导入希沃后**部分文字自己折成两行、或与下一行叠在一起**，看起来像"文字折叠"。

**原因**：SVG 的 `<text>` 没有盒子，只有一段字形；PPTX 有文本框，且希沃会按框宽**重新折行**。若框宽只按字形量出来的宽度给（旧行为：字形宽 + 每侧 0.1em ≈ 32px 字体仅 3px 余量），希沃就会提前几像素折行——中文正文尤其明显，因为一个汉字折下去立刻看得出来。

**已解决**：转换器（`svg_to_pptx/drawingml_elements.py`）现在给每个文本框**每侧多加 0.5em 余量**。文本框本身透明（`noFill`、无描边），加宽**不影响任何视觉效果**，纯粹是给渲染器留出余量，让它不会重新折行。

- **无需在 SVG 里做任何事**——这是导出器的默认行为，本模板 14 页均已受益。
- **加宽只作用于框，不动文字原点**：文字位置与加宽前逐像素一致，不会整体左移或右移。
- **需要微调**时设环境变量 `PPT_TEXT_SLACK`（em/侧，默认 `0.5`，`0` 关闭）；想把某个框精确对齐到卡片宽度，在该 `<text>` 上加 `data-box-width="1160"`。
- **排障提示**：若仍遇到折叠，先确认 `PPT_TEXT_SLACK` 没被设成 `0`，**不要**去缩小字号或删减文案——根因是框宽，已经处理过了。

### 使用检查清单

导出后导入希沃前，逐项确认：

- [ ] 文件为 `.pptx` 格式
- [ ] 画布 16:9（1280×720 或等效）
- [ ] 页面内容未越过 y=648
- [ ] 文字字体为黑体 / 微软雅黑
- [ ] 图片总大小在几百 KB 量级（不是几 MB）
- [ ] 无 SmartArt / 3D / 复杂自定义动画
- [ ] 导入希沃后抽查 1–2 页正文，确认**没有文字自己折行或叠行**（若出现，见 §VIII.6）
